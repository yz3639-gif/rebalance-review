# Data implementation evidence

Checked 2026-10-05. The registry records security identity, issuer inception and USD denomination; it does **not** certify a user's imported prices, adjustment methodology, redistribution rights, or accuracy. The user's specific dataset must independently identify its source, USD units, adjusted-close/total-return basis and rights. No issuer prices or holdings tables were copied into the product.

Inception is not always the first exchange-trading date: issuer regional pages distinguish VOO inception 2010-09-07 from listing 2010-09-09, and VXUS inception 2011-01-26 from listing 2011-01-28. Currency evidence is explicit, not inferred from a dollar symbol:

- SPY and GLD issuer listing tables name their US exchanges and USD trading currency.
- SHY, IEF, TLT, TIP and LQD iShares Swiss site **Listings** tables identify the same US tickers on NASDAQ/NYSE Arca with USD, alongside separate non-US currency listings. Direct URLs are in `currency.sourceUrl`.

Regional marketing location is not treated as domicile; US identifiers and matching US issuer factsheets are cross-checked. VTI's regional page also contains Australian cross-listing material, so its Australian trading currency is not used for the US ticker.
- QQQ's [issuer key-facts document](https://www.invesco.com/content/dam/invesco/hk/en/pdf/kfs/Invesco_QQQ_KFS_EN.pdf) establishes USD base currency of the same US fund; foreign exchange trading counters are separate and unsupported. The US product page establishes the intended QQQ identity.

Registry denomination evidence never replaces explicit USD confirmation for an uploaded file: users may obtain foreign-currency series of the same cross-listed security. The 16 recognized symbols are separate from the capacity limit of 20 noncash positions; unsupported positions remain visible and excluded only with partial-analysis confirmation.

## Session calendar

`us-equity-calendar.json` contains 355 weekday closures and implies 9,820 sessions for 1990-01-01 through 2028-12-31, generated by `generate_calendar.py` using pinned `exchange-calendars==4.13.2`. Scheduled 2026–2028 dates were reviewed against the official NYSE table on 2026-10-06. The product validates membership/completeness in TypeScript. This is a daily calendar; early-close days remain valid sessions.

Reference: [exchange_calendars](https://github.com/gerrymanoim/exchange_calendars), an Apache-2.0 project with historical Quantopian calendar work. Only generated factual dates are included; no upstream implementation was copied. The repository's locked verification environment supplies the pinned package. Run `uv sync --locked`, then `uv run --locked python src/data/generate_calendar.py --check` for a non-writing reproduction check. Omit `--check` only for a reviewed regeneration; `--output` can target a temporary snapshot. Tests check official 2026–2028 holiday dates, early closes, Juneteenth introduction, year-end New Year observance, extraordinary closures, out-of-range rejection, and the 90-day maintenance warning.

Primary checks: [NYSE 2026–2028 holidays](https://www.nyse.com/trade/hours-calendars), [2026 exchange calendar](https://www.nyse.com/publicdocs/nyse/ICE_NYSE_2026_Yearly_Trading_Calendar.pdf), [2025 Carter closure notice](https://www.nyse.com/publicdocs/nyse/markets/american-options/rule-interpretations/2025/National_Day_of_Mourning_20250102.pdf). The 2027-12-31 session remains open because Saturday New Year 2028 has no preceding Friday closure. New extraordinary closures and dates outside the recorded range require a reviewed update. Maintenance expiry does not invalidate historical inputs already inside the snapshot. Synthetic examples use explicitly illustrative weekdays, never observed exchange history.

## Permissions and provider status

`rightsDecision` separately governs in-session display, raw/derived persistence, raw/derived export and public display; `manifestRightsDecision` additionally applies source-policy and raw-retention restrictions. Unknown evidence or invalid verification dates deny all actions. Export requires both the corresponding persistence permission and export permission. File possession is not treated as a license. CSV export neutralizes spreadsheet formulas.

As of 2026-10-06, the Tiingo BYOK adapter is implemented using each user's token through a restricted same-origin proxy to fixed Tiingo endpoints. It requests EOD `adjClose`, described in the [official EOD documentation](https://www.tiingo.com/documentation/end-of-day) as adjusted for splits and distributions. It uses operation-only raw history, no shared token, and no application logging or persistent caching of provider responses. Actual authenticated access and the user's account entitlement remain separate verification gates.

The default `tiingo-byok` policy permits calculation/display but caps raw and derived persistence, full-report/archive export and public display regardless of permission booleans. The [official terms](https://app.tiingo.com/tos/) restrict Starter/trial raw retention and require qualifying derived outputs to be non-reconstructive; possession of a personal key does not establish storage or report-export rights. The optional decision-only PDF exports user-entered allocations, assumptions and reasoning; it omits provider metadata, observed history, risk estimates, coverage results and charts. It is distinct from a full report containing derived market results.

The custom REST adapter supports browser-accessible HTTPS JSON/CSV APIs with explicit request/response mapping and user-declared USD adjustment basis and permissions. Without raw-storage permission, observations use operation-only retention. Derived persistence/export is independently controlled. Neither the adapter nor a checkbox verifies a provider license. See [provider integration details](../../docs/PROVIDERS.md) for supported authentication, CORS boundaries, and sanitization behavior.

## v1.2 current US listing catalog

`etf-catalog.json` is a versioned snapshot of the official Nasdaq Trader symbol directories: [Nasdaq-listed](https://www.nasdaqtrader.com/dynamic/SymDir/nasdaqlisted.txt), [other exchanges](https://www.nasdaqtrader.com/dynamic/SymDir/otherlisted.txt), and [field definitions](https://www.nasdaqtrader.com/trader.aspx?id=symboldirdefs). Only `ETF=Y` and `Test Issue=N` enter the catalog. The snapshot records download date, file-creation timestamps and source SHA-256 hashes. ETF flags include some exchange-traded products; they do not establish non-leveraged status, USD quotation, inception, Tiingo availability or suitability. It is a current listing directory, not a point-in-time historical investment universe. Existing issuer-verified inception/currency annotations for the original demo instruments remain distinct from listing identity.

`node scripts/update-etf-catalog.mjs` downloads and reports proposed changes without writing; append `--write` to apply a reviewed refresh. Malformed sources, duplicates, implausible counts and large removals reject the update and preserve the prior snapshot. Archived review identities are frozen separately. Nasdaq metadata is externally sourced factual directory data, not code licensed by this project's MIT license; public availability is not represented as an open-data redistribution grant. Public distribution terms remain a release review item.

The original 16 instruments remain `DEMO_SYMBOLS`; the calculation and provider limit is independently `MAX_REVIEW_ASSETS=50`. Tiingo requests validate live metadata at its fixed `/tiingo/daily/{ticker}` endpoint before adjusted prices. Its start/end dates describe **provider coverage**, not fund inception ([Tiingo EOD documentation](https://www.tiingo.com/documentation/end-of-day)). A selected listing without issuer-verified USD metadata requires an explicit user confirmation of USD quotations. Every asset must reach the requested final session; shorter initial coverage is recorded, and the engine enforces 253 common prices. Provider-acquisition metadata contains no credential or price observations.

**Cash symbols:** use `CASH`, `USD CASH`, or `USD_CASH` for modeled cash. Bare `USD` is the Nasdaq-listed ProShares Ultra Semiconductors ETF and is never converted to cash in v1.2 input. Legacy archives containing ambiguous raw `USD` must be resolved explicitly rather than silently reinterpreted.
